## Done — three model milestones
1. **C1 rate adaptation measured** ([results/c1_rate_adaptation](../../results/c1_rate_adaptation/README.md)). One mother code with puncture/shorten masks reaches f = 1.38–1.87 over Q = 2–6% and cannot serve Q = 1% at all. Puncturing is reliable only up to ~10% of positions.
2. **L2 bit-true model and E2** ([results/e2_quantisation](../../results/e2_quantisation/README.md)). The spec's fixed-point defaults show **zero quantisation loss** against the float model, and sit exactly on the cliff: W_MSG 5 or W_APP 6 collapse, 7 bits gains nothing. Spec section 2.1 statuses moved from TBC to confirmed.
3. **Numba kernels, bit-exact with the reference** ([results/bench_decoder](../../results/bench_decoder/README.md)). 5–21× faster; at n = 65,536 a 10⁵-frame point costs about 45 minutes on one core, so publishable sample sizes are now affordable.

## Decisions forced by measurement
- **Two mother codes, not one** (docs/06 §2a, docs/03 open items). The single-code assumption in REQ-FUN-03 does not survive the puncture budget.
- The puncturable subset must be **larger than the punctured set**: puncturing every heavy column strips the graph and fails, while puncturing part of it helped (FER 0.96 → 0.24 at 3%).
- W_APP = 7 suffices; the spec's 8 carries one bit of margin worth revisiting when the BRAM budget is tight.

## Later in W42 — M3 code design, parallel sweeps, key-rate curves
- **Parallel sweeps** (`model/sweeps.py`): 12 points at n = 8,192 take 6.4 s on one core, 1.2 s on eleven.
- **Density evolution** (`model/de.py`) for normalized min-sum on the BSC, with the exact (sign, magnitude) check-node update. A first version using the usual independence factorisation gave a (3,6) threshold of 12.5%, above the 11.0% Shannon limit; a test now guards that.
- **M3 code design took three passes**, each one teaching something ([results/m3_code_design_v3](../../results/m3_code_design_v3/README.md)):
  1. masks built for a target efficiency — every point failed; efficiency is an outcome, not an input;
  2. threshold-driven rates — high-rate code worked, low-rate code failed where masks punctured 24-30%;
  3. **mother code at the top of its range, shorten downward, puncture only inside the 10% budget — every point decodes, FER 0.00 across Q = 1-8%** at n = 65,536, zero undetected errors, rank check passed on every mask.
- **Efficiency reached f = 1.29-1.56** against the 1.15 target. The ensemble's threshold gap caps f at ~1.22 before any finite-length margin, so the requirement needs a numerically optimised degree distribution rather than better masks.
- **Key-rate curves** ([results/e5_key_rate](../../results/e5_key_rate/README.md)): efficiency costs ~4% of the key below 100 km and decides maximum range — at 200 km, f = 1.6 yields nothing while f = 1.0 still gives ~1 kbit/s.
- **Vivado decoder guide** ([stages/](../stages/00-overview.md)) plus the decoder micro-architecture ([blocks/ldpc-decoder](../blocks/ldpc-decoder.md)), and two generators: test vectors from the L2 model, and the base matrix as .mem/.coe/.svh for the RTL.
